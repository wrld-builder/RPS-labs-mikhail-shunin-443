# Отчёт по лабораторной работе №3

## Цель работы
Разработать веб-приложение с графическим интерфейсом и интеграцией базы данных, позволяющее пользователю регистрироваться, работать с массивами целых чисел, сортировать их алгоритмом из ЛР №2 (реализована пирамидальная сортировка), а также сохранять результаты и выполнять автономные интеграционные тесты.

## Задание
1. Настроить систему контроля версий и вести разработку в ветке `develop-lab3`.
2. Развернуть БД, обеспечивающую хранение отсортированных и исходных массивов целых чисел.
3. Создать набор интеграционных тестов, проверяющих массовые вставки, чтение/сортировку и очистку данных для наборов из 100/1000/10000 массивов.
4. Реализовать графический интерфейс, соблюдающий ключевые UI/UX-эвристики (видимость статуса, соответствие метафорам реального мира, управляемость, согласованность, гибкость/минимализм, помощь и справка).
5. Сформировать клиент-серверное веб-приложение с регистрацией, авторизацией, вводом и генерацией массивов, сортировкой по пирамидальному алгоритму, сохранением исходных/отсортированных данных и просмотром ранее сохранённых массивов.
6. Подготовить отчёт о проделанной работе.

## Используемые технологии
### База данных
- **SQLite + better-sqlite3**. Выбран файл базы `server/data/app.db`, создаваемый автоматически. Плюсы: не требует отдельного сервера, транзакционность, хорошая производительность для локальных сценариев. Минусы: отсутствие параллельного доступа на уровне клиента-сервер, ограничение по размеру файла, необходимость миграций при переключении на серверную СУБД.

### Графический интерфейс
- **React + Vite**. SPA с компонентной структурой, контроли состояния и сетки отвечает за интерактивные формы, таблицы и уведомления. Плюсы: скорость разработки, мгновенный Hot Reload, удобная декомпозиция. Минусы: требуется сборка, размер бандла, необходимость настройки взаимодействия с API.
- Дополнительно: модульная структура (компоненты уведомлений, справки, таблицы), современный дизайн на базе CSS без внешних UI-библиотек.

## Структура базы данных
| Таблица | Поле | Тип | Назначение |
| --- | --- | --- | --- |
| `users` | `id` INTEGER PK | Цифровой идентификатор пользователя |
| | `username` TEXT UNIQUE | Логин (хранится в нижнем регистре) |
| | `password_hash` TEXT | Хэш пароля (bcrypt) |
| | `created_at` TEXT | Время регистрации (UTC) |
| `arrays` | `id` INTEGER PK | Идентификатор сохранённого массива |
| | `user_id` INTEGER FK | Владелец записи |
| | `label` TEXT | Произвольная подпись |
| | `original_data` TEXT | JSON-массив исходных чисел |
| | `sorted_data` TEXT | JSON-массив после пирамидальной сортировки |
| | `save_original` INTEGER | Флаг сохранения исходных данных |
| | `save_sorted` INTEGER | Флаг сохранения отсортированных данных |
| | `created_at` TEXT | Время создания записи |

Тестовый проект использует отдельный файл БД `tests/data/integration.db`, путь задаётся через `DB_PATH` перед импортом серверных модулей, чтобы тесты не затрагивали основную базу.

## Интерфейс и соблюдение эвристик UI/UX
- **Видимость статуса системы**: уведомления по каждому действию, индикаторы загрузки списков и состояния авторизации.
- **Соответствие реальному миру и согласованность**: русскоязычные подписи, группировка действий (авторизация, работа с массивом, история), единая визуальная система карточек.
- **Управляемость и гибкость**: пользователь может переключаться между ручным вводом и генерацией массива, выбирать что сохранять (оригинал/результат), удалять записи и обновлять список.
- **Минималистичный дизайн**: на экране только четыре панели (авторизация, рабочая область, история, справка), что исключает перегрузку информацией.
- **Помощь и предотвращение ошибок**: блок справки поясняет сценарий, формы имеют валидацию, статусные сообщения уведомляют о некорректных данных.
- **Наличие справки**: в интерфейсе есть отдельная панель с подсказками, описывающая алгоритм действий и связь с эвристиками.

## Инструкции по запуску
1. **Сервер**
   ```bash
   cd server
   npm install
   npm run dev
   ```
2. **Клиент**
   ```bash
   cd client
   npm install
   npm run dev
   ```
   Переменная `VITE_API_URL` задаёт адрес API (по умолчанию `http://localhost:4000/api`).
3. **Интеграционные тесты**
   ```bash
   cd tests
   npm install
   npm start
   ```
